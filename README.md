# KiCad DRL → CNC3018 (GRBL TAP)

**Портфолио:** [страница лабораторной автоматизации и остальные инструменты](https://maxstrix324.github.io/project/lab-automation/). Ниже приведены актуальные возможности, ограничения и инструкции этого репозитория.

Конвертер файлов сверловки **KiCad / Excellon (`.drl`)** в G-code **GRBL (`.tap`)** для станков класса **CNC 3018**. Python 3, **без сторонних библиотек**. Проверен программно на четырёх реальных DRL-файлах, экспортированных из **KiCad 10.0.1**. **На физическом станке обновлённая версия не проверялась.**

> ⚠️ Программа генерирует управляющие команды для реального оборудования. Перед запуском обязательно проверьте размеры, ноль Z, ориентацию платы, рабочую область станка, программу в визуализаторе Candle/UGS и выполните сухой прогон над платой. Вы несёте ответственность за параметры сверления и безопасность станка.

## Что умеет

- Читает метрические DRL KiCad с форматом `FORMAT={3:3/...}` и **keep zeros**.
- Учитывает выбранные инструменты (`T1`, `T2`, …), а не только их объявления в заголовке.
- **Создаёт один `.tap` на один входной DRL**, объединяя все координаты независимо от исходного диаметра. Шпиндель включается один раз; в G-code нет `G4`, `M0`, `M1` или `M6`.
- Сохраняет координаты KiCad, в том числе отрицательные Y. **По умолчанию сортирует все точки по вертикальным полосам X**, сверлит последовательно по Y сверху вниз или снизу вверх («змейка»). Направления выбираются по минимальной суммарной длине холостых XY-перемещений между полосами; для нестандартной геометрии сохраняется более короткий вариант обычной сортировки X/Y.
- Позволяет задать безопасную Z, высоту подхода, глубину, подачу и скорость шпинделя `S`. **Автоматическая задержка раскрутки не реализована:** после `M3` программа не вставляет `G4` и сразу переходит к перемещениям.
- **Высверливает фрезеруемый контур отдельными погружениями**, располагая точки вдоль режущих участков `G01` и пазов `G85` с шагом не более 1 мм по умолчанию. Холостые перемещения `G00` не сверлятся. Это перфорация, а не боковое фрезерование; шаг регулируется `--contour-step`.

## Настройки и графический интерфейс (Windows 10/11)

В комплекте есть **`gui.bat`** — настольное окно на стандартном Python Tkinter, без сторонних библиотек. **`start.bat` сохранён для автоматической конвертации без окна.**

1. Скачайте **Code → Download ZIP** и распакуйте архив целиком.
2. Запустите **`install.bat`** для проверки Python 3.10+.
3. Запустите **`gui.bat`**, выберите входной `.drl` или папку; при желании укажите каталог TAP.
4. Отредактируйте Z, подачу, шпиндель, шаг точек контура и ширину вертикальных полос. Выберите режим контуров.
5. Нажмите **«Сохранить настройки»**, затем **«Создать TAP»**. После конвертации появятся отчёт и схематическая траектория XY.

Все параметры сохраняются в **`settings.json`** рядом с программой и одинаково используются из `gui.bat`, `start.bat`, `auto_convert.py` и `drl_to_tap.py`. Значения проверяются до начала обработки; неверный JSON или небезопасное соотношение координат Z приводят к ошибке.

Пример `settings.json`:

```json
{
  "z_safe": 5.0,
  "z_approach": 0.5,
  "z_drill": -2.4,
  "feed": 50.0,
  "spindle": 10000,
  "contour_step": 1.0,
  "column_width": 1.0,
  "slot_mode": "drill",
  "source_path": "",
  "output_dir": ""
}
```

`slot_mode`: `drill` — высверливать контур; `skip` — только обычные отверстия; `strict` — ошибка при наличии контура. Пустой `source_path` — автопоиск рядом с программой и в `input/`; иначе файл или папка (вложенные папки поддерживаются). Пустой `output_dir` — TAP рядом с DRL. Относительные пути в JSON разрешаются относительно папки программы.

Аргументы командной строки **перекрывают настройки**, но не переписывают JSON: `start.bat --column-width 2`, `start.bat --config my_settings.json`. Графическое окно редактирует основной `settings.json`.

Предпросмотр показывает только перемещения XY между точками сверления. Он не заменяет проверку кода в Candle/UGS и сухой прогон. При объединении разных диаметров в один TAP физически используется одно установленное сверло.


**Раскрутка шпинделя:** программа намеренно генерирует непрерывный TAP без пауз. Перед первым погружением убедитесь, что шпиндель уже набрал безопасную скорость. Если используете контроллер без гарантированной задержки выхода на обороты, запускайте шпиндель отдельно или проверяйте первую точку на холостом прогоне. Настройка `--dwell` пока не решает эту задачу. Не начинайте обработку при недостаточных оборотах.

## Установка и запуск (Windows 10/11)

1. Скачайте **Code → Download ZIP** и распакуйте **весь архив** в одну папку (не только BAT-файлы).
2. Один раз запустите **`install.bat`**. Он проверит **реальный запуск Python 3.10+**, при необходимости предложит установить Python 3.13 через `winget` и создаст папку `input`. Надпись «Python verified» означает готовность интерпретатора, а не успешную обработку DRL.
3. Положите один или несколько KiCad `.drl` **рядом с `start.bat`** или в папку **`input`** (в ней разрешены вложенные папки).
4. Для автоматической конвертации запустите **`start.bat`**; для окна — **`gui.bat`**. **Имя файла вводить не нужно.** Программа найдёт DRL автоматически и создаст **один TAP рядом с каждым DRL**, с тем же именем (например, `board.drl` → `board.tap`). Файлы из `examples/` в автоматическом режиме не обрабатываются.
5. Результаты и возможные ошибки сохраняются в **`conversion_report.txt`** рядом с `start.bat`. Если один DRL содержит ошибку, остальные всё равно будут обработаны.
6. Проверьте полученные траектории в **Candle**, **UGS** или аналогичном GRBL-контроллере до запуска станка.

Вместо автоматического поиска можно перетащить один или несколько DRL-файлов **или папку** на `start.bat`. Для папки будет выполнен рекурсивный поиск. Параметры сверления (`--z-drill`, `--feed` и т. д.) также работают с `start.bat`.

Примеры из командной строки:

```bat
start.bat
start.bat "C:\My Boards\board.drl"
start.bat "C:\My Boards" --z-drill -1.8
start.bat --contour-step 0.8
start.bat --column-width 2
start.bat --config my_settings.json
start.bat --skip-slots
start.bat --strict-slots
```

**Контурная перфорация:** если в DRL есть `G00`→`G01` или `G85`, программа сверлит точки **вдоль режущих сегментов**, включая начало и конец, с максимальным шагом `--contour-step` (1 мм по умолчанию). Каждая точка — вертикальное погружение с подъёмом на безопасную Z; **бокового резания нет**. `G00` без следующего режущего участка — только перемещение, сверлить его нельзя. `--skip-slots` выключает контурную перфорацию, `--strict-slots` запрещает обработку файла с пазами. В отчёте указаны обычные отверстия, режущие сегменты и точки контура.

**Вертикальная сортировка:** применяется после объединения обычных и контурных точек. Точки разбиваются на полосы шириной `--column-width` (по умолчанию 1 мм), каждая полоса проходится по Y в одном направлении. Выбор чередующихся направлений уменьшает возвраты по Y там, где это возможно. Для проверки в `conversion_report.txt` записана сумма перемещений XY между позициями сверления до и после сортировки (не включая движение от неизвестного рабочего нуля и движения по Z). Сортировка **не меняет координаты, глубину, размер сверла или механику станка**; повышение точности нельзя гарантировать без проверки люфта и калибровки.

**Один физический инструмент:** один TAP с отверстиями разных исходных диаметров **не даёт автоматической смены сверла**. Все отверстия фактически будут просверлены тем сверлом, которое установлено в станке. Для точной обработки разных диаметров одним инструментом этот режим не подходит: нужно раздельное сверление со сменой инструмента. Также близкие отверстия вдоль контура могут перекрываться и создавать значительную нагрузку; подбирайте шаг, сверло и режимы экспериментально.

Если в папке нет ни одного DRL, появится понятное сообщение — запрос ввода имени файла больше не используется. Интернет требуется только для установки Python; сторонние Python-библиотеки не нужны.

## Экспорт сверловки из KiCad

В **PCB Editor → File → Fabrication Outputs → Drill Files** экспортируйте файл Excellon в **миллиметрах**, абсолютные координаты, **keep zeros**. Для обычной сверловки используйте `.drl` с круглыми отверстиями. Пазы могут присутствовать в таком же файле и требуют отдельной обработки.

Координаты **не перемещаются в начало платы** автоматически. В ряде экспортов KiCad Y отрицательный — это нормально для исходных данных, но перед запуском станка необходимо выставить правильный **рабочий ноль X/Y**. Z=0 в типовом сценарии — верх поверхности платы.

## Командная строка

```powershell
python drl_to_tap.py "C:\Projects\board.drl"

# Отдельный каталог; один TAP с обычными отверстиями и перфорацией контура
python drl_to_tap.py "C:\Projects\board.drl" --output-dir "C:\Projects\cnc" --contour-step 1

# Глубина, безопасная высота и подача
python drl_to_tap.py board.drl --z-safe 5 --z-approach 0.5 --z-drill -1.8 --feed 40 --spindle 1000

# Более широкие вертикальные полосы (для крупных плат)
python drl_to_tap.py board.drl --column-width 2

# Альтернативный конфигурационный файл
python drl_to_tap.py board.drl --config my_settings.json
```

| Аргумент | По умолчанию | Значение |
| --- | ---: | --- |
| `--z-safe` | `5` | Безопасная высота над Z=0, мм |
| `--z-approach` | `0.5` | Быстрое опускание до высоты подхода, мм |
| `--z-drill` | `-2.4` | Рабочая глубина, мм |
| `--feed` | `50` | Подача Z в мм/мин |
| `--spindle` | `10000` | **Значение GRBL S**, не гарантированные об/мин |
| `--dwell` | `0` | Устаревший параметр совместимости: значение принимается, но **не влияет на G-code**. Пауза `G4` не добавляется. |
| `--output-dir` | рядом с DRL | Папка с выходными файлами |
| `--contour-step` | `1.0` | Максимальный шаг сверления вдоль режущего контура, мм |
| `--column-width` | `1.0` | Ширина вертикальных полос по X для прохода по Y, мм |
| `--skip-slots` | выключено | Игнорировать пазы и создать TAP только для обычных круглых отверстий |
| `--strict-slots` | выключено | Считать наличие фрезеруемых пазов ошибкой; ничего не генерировать |

**Важно про шпиндель:** в GRBL значение `S` зависит от настройки контроллера **`$30`** (например, `$30=1000` либо `$30=10000`). Убедитесь, что используете корректную шкалу; `S10000` в программе не означает автоматически 10 000 физических об/мин.

## Какой получается G-code

```gcode
G21
G90
G94
G0 Z5.000
M3 S10000
G0 X5.000 Y-5.000
G0 Z0.500
G1 Z-2.400 F50
G0 Z5.000
M5
M2
```

Это сокращённый пример, а не готовая полная программа. Полный TAP содержит все точки сверления и один запуск шпинделя. Смена инструмента отсутствует.

## Ограничения

- Только **метрические** DRL с явно указанным форматом координат или десятичными координатами; поддержка Excellon zero-suppression (`LZ`/`TZ`) пока не реализована.
- Контуры `G01/G85` превращаются в **отдельные точки сверления**. Это не чистовая резка, отверстия не гарантируют отделение контура. Для выключения используйте `--skip-slots`. Неподдерживаемые команды по-прежнему вызывают ошибку.
- Не поддерживается автоматическая пробивка нескольких глубин (peck drilling), компенсация люфта, автоуровень, корректировка толщины заготовки и проверка пределов перемещения станка.
- Программа не управляет самой CNC3018 и не гарантирует совместимость с любой прошивкой: выход предназначен для **GRBL**.
- При повторном запуске соответствующие TAP-файлы перезаписываются.

python -m unittest discover -s tests -v

На предоставленных четырёх DRL из KiCad 10 проверена читаемость файлов и корректное разделение круглых отверстий по диаметрам. В двух исходниках дополнительно найдены продолговатые пазы; обработка путей `G01/G85` теперь тестируется. Геометрия и механическая безопасность для конкретной платы требуют отдельной проверки. Исходные PCB-проекты в репозиторий не включены.
